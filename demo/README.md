# Демо-стенд «Протоколу»

Окремий VPS з вигаданою «Демо-клінікою», тестовим входом і скиданням однією командою (ТЗ «демо клиники и тренировки», крок 1; D170). Прод не зачіпається: там `CLINIC_IDENTITY_V2` вимкнений, клініка не створюється.

## Що тут працює

| Сервіс | Що робить | Назовні |
| --- | --- | --- |
| `web` (Caddy) | застосунок, зібраний для стенду (свій API, смуга «Демо · дані вигадані» на всіх екранах); TLS для трьох адрес | `demo.<домен>`, `api.demo.<домен>`, `idp.demo.<домен>` — порти 80/443 |
| `api` | той самий сервер, що на проді, з `DEMO=1` і `CLINIC_IDENTITY_V2=on` | лише через Caddy |
| `idp` | тестовий вхід OpenID Connect: адміністратор, ендокринолог, травматолог; другий крок — код `000000`, тож `amr` несе MFA, як вимагає D152 | лише через Caddy |
| `mailpit` | пастка для листів-запрошень: усе ловить, нікуди не пересилає; SMTP лише з STARTTLS і паролем | ні: вебінтерфейс на `127.0.0.1:8025` самого VPS |

## Замки

- Сервер з `DEMO=1` не стартує, якщо `APP_ORIGIN` не `demo.<домен>` (або localhost) чи вхід не через `idp.demo.<домен>`.
- Сервер без `DEMO=1` не стартує, якщо його `OIDC_ISSUER` вказує на `idp.demo.…`; а будь-який issuer, що в discovery називає себе демо (`x_protocol_demo_idp`), поза стендом нікого не впускає.
- Тестовий вхід не стартує без `DEMO=1` і поза `idp.demo.<домен>`.
- `demo:reset` відмовляє без `DEMO=1` (він є лише в `demo/compose.yml`).

## Розгорнути (робить власник: DNS і VPS)

1. VPS з Docker. DNS: `demo.<домен>`, `api.demo.<домен>`, `idp.demo.<домен>` → IP цього VPS.
2. На VPS: `git clone` репозиторію, потім `sh demo/setup.sh demo.<домен> <e-mail для сертифікатів>` — створює `demo/.env` і `demo/.secrets/` (не в git), секретів не друкує.
3. Необов’язково: власний ключ ІІ для стенду в `demo/.env` (`ANTHROPIC_API_KEY`) — фото, меню, помічник. Порожньо — ці функції на стенді вимкнені.
4. `docker compose -f demo/compose.yml up -d --build`, потім `npm run demo:reset`.
5. Перевірка: `https://api.demo.<домен>/health` → `"demo": true`.

## Скинути перед показом

`npm run demo:reset` — база з нуля, міграції, «Демо-клініка» з трьома працівниками; усі видані раніше коди зникають разом зі старою базою. API на час скидання зупинений.

## Пошта

`ssh -L 8025:127.0.0.1:8025 <vps>` і відкрити `http://localhost:8025` — там листи-запрошення стенду.

## Що проговорити лікарю на показі

З `docs/clinic-secure-delivery.md`: для демо допустимо, для справжніх пацієнтів — ні: план зберігається відкритим текстом до погашення коду (ACCESS-07-B), ім’я лікаря приходить від клієнта (ACCESS-07-A).
