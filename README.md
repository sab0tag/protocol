# Протокол

Особистий веб-застосунок (PWA): перетворює план лікаря на щоденні дії — їжа, ліки, вода, тренування, самопочуття.
**Лікар вирішує, застосунок допомагає виконати.** Нічого не діагностує й не призначає.

ТЗ і прийняті рішення — [SPEC.md](SPEC.md). Етапи **M1–M4** готові. Працює на https://protocol.beyondthesignal.to (Vercel, оновлюється з кожним push у `main`).

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173, з телефона — за IP комп'ютера в тій самій мережі
npm test           # модульні тести (Vitest)
npm run build      # перевірка типів + збірка в dist/ (PWA, працює офлайн)
```

## Дані й приватність

- Усе зберігається на пристрої (IndexedDB), шрифт — усередині збірки. Назовні застосунок ходить лише до свого
  сервера (`server/`) і лише якщо людина сама увімкнула:
  - **синхронізацію** (Ще → Синхронізація) — записи шифруються на пристрої кодом синхронізації (AES-GCM);
    сервер бачить тільки зашифровані записи з непрозорими ключами й не може їх прочитати (SPEC.md D31);
  - **фото їжі** — зменшене фото без метаданих іде через сервер до Claude (Anthropic) і ніде не зберігається;
    медичні дані не надсилаються (D32);
  - **«Меню на завтра»** — з окремої згоди в Claude йдуть цілі плану й обмеження лікаря (без імені, ваги,
    аналізів і ліків); меню перевіряється правилами застосунку й записується як «заплановано» (D33);
  - **нагадування** (Web Push) — сервер знає лише час і загальне слово («Обід», «Ліки»), подробиці телефон
    показує зі своїх даних (D34).
- Особистий план: створіть `src/data/seed.local.ts` (у `.gitignore`) з функцією `localPlan(): Plan` —
  вона підхопиться при першому запуску замість прикладу з `seed.example.ts`.
- Репозиторій приватний. Справжні медичні дані в git не потрапляють.

## Структура

```
src/app        маршрути
src/screens    екрани (День, Додати їжу, …)
src/components спільні елементи (навігація, нижній лист)
src/domain     модель даних, розрахунок КБЖУ, (M2) правила перевірки страв
src/data       Dexie, вбудована база (215 продуктів, 19 страв), приклад плану
src/i18n       усі тексти інтерфейсу (українською)
src/sync       шифрування, синхронізація, клієнт API
tests/unit     Vitest
server/        API на Hetzner (Hono + node:sqlite + Anthropic SDK)
```

## Сервер (`server/`)

```bash
cd server && npm install
npm test
PORT=8099 ALLOWED_ORIGINS=http://localhost:5173 npm start   # фото вимкнене без ANTHROPIC_API_KEY
VITE_API_URL=http://localhost:8099 npm run dev               # (у корені) застосунок проти локального сервера
```

Прод: `https://api.beyondthesignal.to`, контейнер у `/opt/protocol-api` на сервері Харчоблоку; Caddy Харчоблоку
проксірує туди через мережу `harch_edge`. Секрети — у `/opt/protocol-api/.env` (див. `server/.env.example`):
окремий ключ Anthropic з лімітом витрат. Оновлення: `rsync` каталогу `server/` і `docker compose up -d --build`.
