# Security review — 18.10.2026 (перед пилотом)

Что проверено: шифрование синхронизации и ключи, восстановление и спаривание, API (авторизация, лимиты, размеры, прокси), заголовки сайта,
push, новые маршруты помощника и лога, соответствие текстов согласий тому, что реально уходит по сети.

## Итог

Серьёзных дыр не найдено. Исправлено 6 мест (D94), записаны 5 осознанных решений.

## Проверено и в порядке

| Что | Как устроено |
|---|---|
| Ключи | 128 случайных бит кода → HKDF-SHA256 с разделением по назначению: id хранилища, ключ доступа, AES-GCM-256, HMAC-SHA256. Ключи не извлекаемы (`extractable: false`) |
| Записи | AES-GCM, случайный IV на каждую запись, имя записи (HMAC «таблиця:id») — как AAD: сервер не может подменить одну запись другой |
| Сервер | хранит хеш ключа доступа (SHA-256), сравнение — `timingSafeEqual`; содержимое и имена таблиц не видит |
| Спаривание | код 40 бит, PBKDF2-SHA256 300 000 раундов, 10 минут, одноразово, лимит 30 запросов в день на адрес |
| Чужое хранилище | каждый маршрут с `:id` — через `authed`; лог помощника, outcome, копии — только своего хранилища |
| Размеры | лимит тела на всех маршрутах записи, квота хранилища 50 МБ, 500 записей за раз |
| Push | только адреса сервисов браузеров (нет SSRF), до 8 устройств; на сервере — время и общее слово («Ліки»), не названия |
| Контейнер | пользователь `node`, не root; `.env` — 600 |
| Внешние запросы приложения | только наш API; индекс препаратов, шрифты, картинки — со своего сайта |
| Фото | перед отправкой перекодируются (место и устройство из EXIF не уходят), на сервере не хранятся |

## Найдено и исправлено (D94)

| # | Что было | Риск | Что сделано |
|---|---|---|---|
| 1 | Нет заголовков безопасности на сайте | при XSS скрипт прочитал бы код синхронизации; сайт можно встроить в чужую страницу | `vercel.json`: CSP (`script-src 'self'`, `connect-src` — только свой сайт и API, `frame-ancestors 'none'`, `object-src 'none'`), `nosniff`, `X-Frame-Options`, `no-referrer`, Permissions-Policy, HSTS. Встроенных скриптов в сборке нет — CSP строгая |
| 2 | У текстовых ИИ-маршрутов (меню, тренировка, помощник) не было общего дневного потолка | много хранилищ с разных адресов — расходы без верхней границы | общий счётчик `ai:all` (800 в день, `AI_PER_DAY`), как у фото |
| 3 | Лимиты по адресу брали первое значение `X-Forwarded-For` | при прокси, который дописывает, клиент подставил бы любой адрес. Сейчас Caddy перезаписывает — проверено: подставной заголовок лимит не обходит | берётся последнее значение — верно при любом поведении прокси |
| 4 | Маршрут outcome без лимита тела | большой запрос нагрузил бы сервер | 4 КБ |
| 5 | Помощник отправлял на сервер названия ограничений плана, даже без лога; в согласии об этом не было | обещание расходилось с сетью | ограничения уходят только при включённом логе, и согласие на лог об этом говорит |
| 6 | Нажатие на уведомление открывало адрес из полезной нагрузки | сервер (или подмена) мог открыть чужой сайт | открывается только страница приложения |

Плюс тексты согласий: бланк анализов — назван список уже записанных показателей; тренировка — названо пожелание.

## Решения, а не дыры (записаны, чтобы не забыть)

1. **Код синхронизации хранится на устройстве открытым текстом** (IndexedDB) — иначе его пришлось бы вводить при каждом запуске. Защита — CSP и сам телефон.
2. **Откат записи сервером** — закрыт для записей, которые устройство уже видело (D96, ниже). **Остаточный риск:** новое устройство при первом подключении берёт то, что дал сервер, — ему не с чем сравнить. Для одного человека и своего сервера — приемлемо; путь закрытия — в бэклоге ниже.
3. **Лог помощника хранится на сервере открытым текстом** — по ТЗ, только с отдельным согласием, 30 дней. Попадает и в ночные копии базы (живут 14 дней), то есть строка может прожить в копии до 14 дней после очистки.
4. **ИИ работает только с синхронизацией** — без неё нужен отдельный токен устройства и защита от расходов.
5. **Восстановление**: потеря кода = потеря доступа к копии на сервере. Защита — напоминание сверить код раз в 30 дней (D40) и файл-копия.

## Пилот: метрики по согласию (D119, 24.10.2026)

Отдельный канал, с синхронизацией не связан: участник — случайный `pid` и секрет (сервер хранит SHA-256 секрета), выдаются при
согласии; ни vault id, ни токен устройства, ни push-подписка в записи пилота не попадают и из `pid` не выводятся.

| Что уходит | Поля |
|---|---|
| Недельная сводка (раз в неделю, итоги ISO-недели) | `v`, `pid`, `week`, `src` (код врача, если введён), `days_in`, `active_days`; `meds` — due, done, skipped, late_30, prn_taken; `food` — days_logged, entries, by_voice, by_text, by_photo, not_found; `plan` — meds, constraints (только число строк), from_photo, photo_rows, photo_rows_edited; `help` — why_opened, topup_shown, topup_taken, danger_card; `rem` — sent, acked (если напоминания включены); `other` — water_days, workouts, wellbeing_days, report_made; `app` — build, platform |
| Опрос 7-го и 30-го дня | `helps` 1–5, `blocker` из 6 вариантов, `report` так / ні / ще не було прийому, `nps` 0–10 |
| «Що заважало» → «Надіслати розробникам» | текст одной записи, по кнопке, каждый раз отдельно; имена заменяются на телефоне и ещё раз на сервере |

Все числа — целые с верхней границей, строки — только из белого списка форматов; схема строгая: лишнее поле → 400, ничего не записано.
Не уходит никогда: имя, возраст, пол, город, даты записей и визитов, названия лекарств и МНН, дозы, диеты, типы ограничений, еда, вес,
самочувствие, симптомы, анализы, свободный текст (кроме заметки по кнопке), vault id, push-подписка, токен устройства.

- **Адрес.** Не хранится: дневной лимит вступлений и проверок кода считается по хешу адреса с солью сервера. Caddy access-лог не пишет
  (директивы `log` нет), приложение тела запросов не логирует.
- **Срок.** Записи пилота — 52 недели, удаляются ночной задачей; участник без записей, вступивший раньше, — тоже.
- **Удаление.** `DELETE /v1/pilot` убирает все строки участника сразу. В ночных копиях они живут до их срока: локально 14 дней,
  во внешнем хранилище (Storage Box) — до 30 дней.
- **Код источника.** Переход по QR — счётчик (день, код) без идентификаторов. В сводной таблице код показывается отдельно только от
  5 участников.
- **Что сервер теперь видит про хранилища (для `stats:ops`).** Недели (не дни), в которые хранилище выходило на связь, 56 недель;
  время первой отправки напоминания (7 дней, как подтверждения); дневные счётчики `stat:*` без id.

## Как проверить самому

- Заголовки: `curl -sI https://protocol.beyondthesignal.to | grep -i -e content-security -e x-frame`
- Подставной адрес: 32 запроса `GET /v1/pair/<любой id>` с разным `X-Forwarded-For` — последние два дают 429.
- Что уходит наружу: DevTools → Network при работе с приложением — запросы только к `protocol.beyondthesignal.to` и `api.beyondthesignal.to`.

## Бэклог безопасности (после пилота)

- **Откат записей сервером — закрыт для всего, что устройство уже видело (D96).** Каждая запись несёт внутри шифротекста время
  изменения; устройство помнит время последней согласованной версии каждой записи и не берёт более старую (допуск 2 минуты на
  расхождение часов), а свою, новую, отправляет снова. Тест: сервер подсовывает план часовой давности — устройство его не принимает.
  Открыто: **новое** устройство при первом входе берёт то, что дал сервер, — ему не с чем сравнить. Что можно сделать: устройства
  сверяют между собой подписанный HMAC «номер последней версии плана» и при расхождении показывают предупреждение.
- **Восстановление после потери устройства** — проверено тестами: новое устройство с кодом получает всё (e2e «two devices»),
  файл-копия восстанавливается на пустом устройстве (unit «export → import»). Перед пилотом — пройти это вручную на телефоне.
