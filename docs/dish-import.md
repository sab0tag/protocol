# Імпорт та експорт страв

У «Мої страви» відкрийте «Імпорт та експорт списку страв».

- Текст або TXT/MD: до 20 рецептів і 12 000 символів. Кожен рецепт містить назву, склад, кількість порцій і, бажано, грами та стан продуктів. Рецепти розділяються порожнім рядком. Після окремої згоди список і назви базових продуктів передаються одним запитом до Claude; план лікаря залишається на пристрої. Назва без складу не перетворюється на вигаданий рецепт.
- JSON: до 200 страв, файл до 2 МБ. Розбір і перевірка відбуваються локально, без ІІ. JSON також можна вставити у текстове поле. «Зразок JSON» завантажує приклад.
- Перед збереженням можна змінити назви, грами готових інгредієнтів і кількість порцій, вибрати частину списку. Нуль грамів прибирає інгредієнт. Перевірки за поточним планом показуються для кожного інгредієнта; це не підтвердження медичної придатності рецепта.
- Дублі назв не вибираються автоматично; вибрані дублі блокують збереження. Імпорт додає нові страви, не оновлює наявні. Збереження атомарне; повідомлення дозволяє скасувати додавання всієї партії.
- «Експорт JSON» зберігає власні страви без внутрішніх ідентифікаторів, для перенесення назад у застосунок. «Експорт списком (TXT)» — читабельні назви й склад на одну порцію. Вбудовані страви не експортуються.

## JSON для підготовки списку в чаті

Обгортка: `{"format":"protocol-dishes","version":1,"dishes":[...]}`. Допускається також масив `dishes` без обгортки. Кожна страва:

```json
{
  "readable": true,
  "name": "Кабачок на парі",
  "portions": 1,
  "note": "КБЖУ на 100 г — орієнтовні.",
  "items": [{
    "said": "Кабачок на парі",
    "base": "",
    "grams": 150,
    "amountSaid": true,
    "kcal": 17,
    "protein": 1.2,
    "fat": 0.3,
    "carbs": 3.1,
    "tags": [],
    "allergens": []
  }]
}
```

`grams` — у готовій страві на всі зазначені порції. `kcal`, `protein`, `fat`, `carbs` і необов’язковий `calciumMg` — **на 100 г цього інгредієнта**, не на всю його вагу. `base` заповнюється лише точною назвою такого самого продукту в такому самому стані з бази застосунку; інакше порожній рядок. Для збігу з базою її нутрієнти мають пріоритет, для решти зберігаються оцінки з файлу. `amountSaid=false` позначає оцінену кількість у попередньому перегляді.

`tags`: lactose, cheese-aged, salty, fried, fatty, sweet, fast-carb, oxalate-high, calcium.

`allergens`: gluten, milk, egg, fish, crustaceans, molluscs, peanut, nuts, soy, sesame, celery, mustard, sulphites, lupin.

Невідомі позначки відкидаються; відсутність позначки не доводить відсутності алергенів. Некоректний JSON, порожні рецепти, від’ємні та нечислові значення відхиляються до запису. Нові ідентифікатори генеруються при збереженні.

Серверні маршрути: `POST /v1/device/dish-list` та `POST /v1/vaults/:id/dish-list`. Та сама автентифікація й квоти, що для одиночного розбору. Одна партія — один виклик моделі, спільний список бази та один запис витрат. Для текстового імпорту потрібно оновити і сервер, і клієнт; JSON працює без нового серверного маршруту.
