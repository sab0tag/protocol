# Пілот: словник метрик (R17, D129)

Звідки цифри: телефон учасника раз на тиждень рахує підсумки завершеного ISO-тижня (пн–нд, за **місцевим** часом телефона) і
надсилає лише числа (`src/domain/pilot.ts`, D120); сервер їх перевіряє й зберігає (`server/src/pilot.ts`, D119);
`npm run stats:pilot` зводить у таблицю (`server/src/stats.ts`). Версія розрахунку — `v` у зведенні (зараз 1) і збірка
застосунку `app.build`. Одиниця спостереження — учасник (`pid`), не людина: два пристрої однієї людини — два учасники
(перенесення участі на інший пристрій не зроблено — це обмеження фіксується в результатах).

## Поля тижневого зведення

| Поле | Визначення | Чисельник / знаменник | Чого з нього **не** можна робити висновку |
|---|---|---|---|
| `active_days` | дні тижня з будь-якою відміткою чи записом (не лише запланованим), тренуванням, самопочуттям, вагою | 0–7 | число відкриттів застосунку чи повноту щоденника |
| `days_in` | днів від першого запису або створення плану до неділі тижня | — | дату початку (вона не надсилається); тиждень із `days_in < 7` — неповний перший |
| `meds.due` | положені дози за 7 днів — та сама «Ліки N з M», що на «Дні» (дата й час внесення, кінець курсу; «за потреби» — ні) | — | — |
| `meds.done` / `due` | дози, **відмічені** прийнятими в застосунку | done ≤ due | доведений прийом препарату |
| `meds.skipped` | дози, явно позначені «Пропущено» | done + skipped ≤ due; решта — не відмічено | пропуск невідмічених |
| `meds.late_30` | відмічені пізніше за час плану більш ніж на 30 хв («час не пам’ятаю» — не запізнення) | late ≤ done | — |
| `meds.prn_taken` | записи прийому «за потреби» (кількість разів, не таблеток) | — | дозу |
| `food.days_logged` | дні з хоч одним з’їденим прийомом їжі | ≤ active_days | що день записано повністю (D128: повноту позначає людина) |
| `food.entries` = `by_voice` + `by_text` + `by_photo` | з’їдені прийоми їжі за способом запису | рівність обов’язкова | — |
| `food.not_found` / `entries` | частини фраз «не знайдено» (прийняті в розборі, без пошуку по буквах) **на 100 записів їжі** | одиниці різні | частку невдалих пошуків |
| `plan.meds`, `constraints` | рядки плану (лише кількість) | — | які саме |
| `plan.photo_rows` | рядки, прочитані з фото висновку цього тижня (крім «без змін» повторного візиту) | — | — |
| `plan.photo_rows_unchecked` | з них не внесені (не відмічені, «Не вносити», «?») | ≤ photo_rows | однозначно погане розпізнавання — людина могла свідомо не вносити |
| `plan.photo_rows_edited` | рядки з фото, виправлені потім у «Плані» | — | повну частоту помилок розпізнавання |
| `help.topup_shown` / `topup_taken` | вечірні підказки показано (раз на день на ціль) / додано в план на вечір (і з «Помічника») | різні джерела | що запропоноване з’їли |
| `help.why_opened`, `danger_card` | «Чому?» відкрито; картку 103 показано (повтор за 10 хв — один раз) | — | — |
| `rem.sent` / `rem.opened` | push прийшов (перший, без повторів і перевірочного) / відкрито з повідомлення; лише з увімкненими нагадуваннями | — | підтвердження прийому |
| `other.*` | дні з водою, тренування, дні з самопочуттям, звіт надруковано / поділено | — | — |
| `app.build` | збірка, якою зведення **сформовано** | — | що весь тиждень пройшов у цій збірці |

Сервер відхиляє зведення цілком (400, нічого не записано), якщо поле зайве, не ціле, поза межами або числа не сходяться: done + skipped > due, late > done,
voice + text + photo ≠ entries, food days > active days, unchecked > rows, ISO-тижня не існує. Телефон такий тиждень більше не
надсилає при кожному відкритті (позначає відхиленим). Повтор того самого тижня замінює запис — пересилання ідемпотентне.

## Зведена таблиця (`stats:pilot`)

| Колонка | Як рахується | Застереження |
|---|---|---|
| `qr`, `consents`, `plan_entered` | переходи за QR коду → згоди (тиждень вступу) → учасники з рядками плану > 0 | код без QR-переходу не видно |
| `ret_w2`, `ret_w5` | **тижневе утримання**: частка учасників з `active_days ≥ 3` у 2-му і 5-му календарному тижні після вступу (тиждень вступу — 1-й) | не точні D7 / D30; відсутнє зведення = неактивний (офлайн-затримку від виходу не відрізнити) |
| `marked`, `marked_w1`, `marked_w4plus` | медіана done / due по учасниках; тиждень 1 і 4+ | позначки, не прийом; лише тижні з due > 0 |
| `partial_weeks` | зведення з `days_in < 7` — перший тиждень, неповний | не порівнювати з повними як рівні |
| `on_time` | частка відмічених доз без `late_30` | — |
| `food_days`, `voice` | медіана днів з їжею; частка голосових записів | — |
| `nf_per_entry` | «не знайдено» на 100 записів їжі | — |
| `photo_edited`, `photo_unchecked` | виправлені потім / не внесені на 100 прочитаних рядків | див. вище |
| `helps_d7`, `helps_d30`, `nps`, `blockers` | середнє «допомагає», NPS 30-го дня, топ-3 перешкоди | лише ті, хто відповів |

Код джерела показується окремим рядком лише від 5 учасників. Це спостереження без контрольної групи: у пілот ідуть найвмотивованіші.

## Перевірка

`server/test/pilot.test.ts`: синтетична когорта з 20 учасників з наперед порахованими підсумками (сходиться вручну), прихований
код з 4 учасників, повтор тижня, суперечливі зведення, тиждень телефона попереду UTC. `tests/unit/pilot.test.ts`: `meds.due`
збігається з «Ліки N з M» кожного дня.
