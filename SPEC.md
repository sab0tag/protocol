# Протокол — ТЗ на прототип v0

Приложение для пациента: превращает план врача в ежедневные действия (еда, лекарства, вода, тренировки, самочувствие) и проверяет еду с учётом диагнозов пользователя.

> Принцип продукта: **врач решает, приложение помогает исполнить.** Приложение ничего не диагностирует и не назначает. Все ограничения и цели вносит пользователь со слов или из заключения врача.

> Решения, принятые при реализации, и открытые вопросы — в разделе **13. Рішення** в конце файла.

## 1. Рамки v0 (исходные, 04.10.2026 — история)

**Что это:** личный веб-прототип (PWA) для одного пользователя. Открывается на айфоне по ссылке и ставится на домашний экран.

**Цель v0:** проверить, будет ли сам автор пользоваться этим каждый день в течение 2–3 недель.

**В v0 есть:**
- План врача: назначения, ограничения с причиной, цели
- «День» как лист заказа: план и факт по времени
- Ввод еды и проверка блюда по правилам
- Чек-лист: лекарства, вода, тренировка, ужин до N часов
- Самочувствие: энергия, настроение, сон (1–5), симптомы
- Журнал тренировок с гирей
- Прогресс: вес по неделям, анализы «было → цель»
- Отчёт для врача: страница для печати и экспорт

**В v0 нет (вне рамок):**
- Сервер, аккаунты, синхронизация между устройствами
- Кабинет врача, чат с врачом
- Распознавание фото и голоса
- LLM и любые внешние API
- Оплата, аналитика, трекеры

## 4. Модель данных

Источник правды в коде — `src/domain/types.ts`. Отличия от исходного ТЗ: `MealItem.manual` (D1), `Plan.profile` и `Plan.onboardedAt` (D17), `DayEntry.checkKey` (D18), `Plan.lastVisit`, `Plan.questions` (D21), `Plan.lastExportAt` (D22), `Food.units`, `Food.aliases`, `MealItem.unit` (D26), `Recipe`, `MealItem.recipe`, `MealItem.components`, таблица `recipes` (D27).

```ts
type ISODate = string;      // "2026-10-04"
type ISODateTime = string;  // "2026-10-04T08:40:00+03:00"

type ConstraintTag =
  | 'oxalate'      // оксалатные камни
  | 'gallbladder'  // сладж / холецистит: без жареного, медленное снижение веса
  | 'lactose'      // непереносимость лактозы
  | 'glycemic'     // нарушенная гликемия / преддиабет
  | 'iron'         // высокий ферритин
  | 'sodium'       // ограничение соли
  | 'custom';

interface Constraint {
  id: string;
  tag: ConstraintTag;
  title: string;        // "Оксалатні камені"
  reason: string;       // "Без шпинату й буряка. Кальцій — у той самий прийом."
  source: string;       // "Уролог, 2025" | "Ендокринолог 02.10.2026" | "Сам"
  active: boolean;
}

interface Prescription {
  id: string;
  kind: 'medication' | 'supplement' | 'test' | 'lifestyle';
  title: string;        // "Вітамін D"
  dose?: string;        // заполняет пользователь со слов врача
  schedule?: { times: string[]; withFood?: boolean };  // ["08:30"]
  dueDate?: ISODate;    // для анализов
  notes?: string;
  source: string;
}

interface Targets {
  kcal?: number;            // 2100
  proteinG?: number;        // 140
  carbsG?: { min?: number; max?: number };  // {max:190} или {min:150} в режиме подготовки
  fatG?: number;            // 80
  calciumMg?: number;       // 1000
  waterMl?: number;         // 2500
  lastMealBy?: string;      // "20:00"
  weightGoalKg?: number;    // 90
  maxWeightLossKgPerWeek?: number; // 0.5
}

interface Mode {             // временный режим, переопределяет цели
  id: string;
  title: string;            // "Підготовка до ОГТТ"
  from: ISODate; to: ISODate;
  targetsOverride: Partial<Targets>;
  notes: string[];          // ["Натщесерце, без кави й тренування в день тесту"]
}

interface Plan {
  constraints: Constraint[];
  prescriptions: Prescription[];
  targets: Targets;
  modes: Mode[];
  nextCheckup?: { date: ISODate; tests: string[] };
}

interface Food {
  id: string;
  name: string;             // "Гречка (суха)"
  per100g: { kcal: number; protein: number; fat: number; carbs: number; calciumMg?: number };
  tags: string[];           // ["grain","slow-carb"] — для правил
}

interface MealItem {
  foodId?: string; name: string; grams: number;
  cooking?: 'raw'|'boiled'|'baked'|'airfryer'|'steamed'|'stewed'|'fried';
  manual?: Nutrients;       // D1: свободная строка — КБЖУ на всю порцию, введённые вручную
}

type EntryKind = 'meal' | 'med' | 'water' | 'workout' | 'note';

interface DayEntry {
  id: string;
  at: ISODateTime;
  kind: EntryKind;
  status: 'planned' | 'done' | 'skipped';
  title: string;            // "Сніданок", "Вітамін D"
  items?: MealItem[];       // для meal
  waterMl?: number;         // для water
  workoutId?: string;       // для workout
  prescriptionId?: string;  // для med
}

interface Wellbeing {
  date: ISODate;
  energy?: 1|2|3|4|5; mood?: 1|2|3|4|5; sleep?: 1|2|3|4|5;
  symptoms: string[];       // ["Тяжкість після обіду"]
  note?: string;
}

interface WorkoutSet { reps?: number; seconds?: number; side?: 'L'|'R' }
interface WorkoutExercise { name: string; target: string; sets: WorkoutSet[] }  // target: "3 × 10"
interface Workout { id: string; date: ISODate; durationMin: number; equipment: string; exercises: WorkoutExercise[]; feeling?: string }

interface WeightLog { date: ISODate; kg: number }
interface LabResult { date: ISODate; name: string; value: number; unit: string; target?: string }
```

Dexie-таблицы: `plan` (одна запись), `foods`, `entries` (индекс по `at`), `wellbeing` (ключ `date`), `workouts`, `weights`, `labs`.

## 5. Экраны и критерии приёмки

Навигация: на телефоне — **нижняя панель вкладок**: День · Їжа · План · Прогрес · Ще. На ширине от 768 px — **боковая колонка иконок**. Иконки и маршруты одни и те же.

### 5.1 День (главный экран)
Лист заказа: строки по времени, колонки **Час · Позиція · Вугл**. Внизу итог дня против целей.
- [x] Показывает все записи дня, отсортированные по времени
- [x] `planned` подсвечен, `done` — с зелёной отметкой, `skipped` — приглушён
- [x] Итог: вуглеводи, білок, кальцій, вода — факт / ціль; при активном режиме — цели из режима
- [x] Баннер активного режима: название, «день N з M», заметки
- [x] Кнопка «Додати рядок» открывает выбор: їжа / ліки / вода / тренування / нотатка
- [x] Тап по строке: «виконано», «пропущено», «редагувати» (свайп — позже)
- [x] Переход на соседние дни стрелками

### 5.2 Додати їжу
- [x] Поиск по встроенной базе продуктов, ввод граммов
- [x] Свободная строка без продукта из базы (название + граммы + вручную КБЖУ)
- [x] Выбор способа приготовления

### 5.3 План лікаря
- [x] Списки: призначення, обмеження (с причиной и источником), цілі, режими, наступний контроль

Автоматически строится из плана: лекарства по расписанию, тренировка (если день тренировки), вода, ужин до `lastMealBy`, цели режима.
- [x] Отметка в один тап, время отметки сохраняется
- [x] Вода: 10 сегментов по 250 мл, тап добавляет сегмент
- [x] Счётчик «4 / 6» в заголовке
- [x] За 2 часа до `lastMealBy` пункт ужина показывает обратный отсчёт

- [x] Енергія, настрій, сон — шкала 1–5, по одному тапу

- [x] Одна запись на день, редактируемая

### 5.6 Тренування

## 6. Проверка блюд — движок правил

Детерминированный, без LLM. Каждое правило срабатывает только если соответствующее ограничение **активно** в плане.

```ts
interface RuleHit {
  itemName: string;
  verdict: 'ok' | 'replace' | 'remove' | 'adjust';
  message: string;        // "Пюре піднімає цукор швидше за рис"
  reason: ConstraintTag;
  suggestion?: string;    // "Рис або гречка"
}
type Rule = (item: MealItem, food: Food | undefined, ctx: RuleContext) => RuleHit | null;
interface RuleContext { plan: Plan; activeMode?: Mode; dayEntries: DayEntry[]; date: ISODate }
```

### 6.1 Начальный набор правил

| Тег | Срабатывает на | Вердикт | Сообщение / замена |
|---|---|---|---|
| `oxalate` | шпинат, щавель, буряк, ревінь, мангольд; мигдаль/кунжут > 30 г | replace | «Багато оксалатів» → броколі, капуста, огірок |
| `oxalate` | приём с оксалатными продуктами без источника кальция | adjust | «Додай кальцій у цей прийом» → 25 г твердого сиру або кефір |
| `gallbladder` | `cooking: 'fried'`, майонез, вершковий соус, сало | replace | «Смажене навантажує жовчний» → аерогриль, запікання |
| `lactose` | молоко, вершки, м'який сир | replace | «Лактоза» → кефір, тверді витримані сири, безлактозне |
| `glycemic` | пюре, білий хліб, булка, цукор, джем, мед, сік, солодкі напої, білий рис | replace/remove | «Швидкі вуглеводи» → гречка, кіноа, бурий рис; булку прибрати |
| `iron` | печінка, если уже была за последние 7 дней или > 120 г | adjust | «Печінка — раз на тиждень, до 120 г» |
| `sodium` | соління, кімчі, квашена капуста, ковбаси > суммарно 2 порций в день | adjust | «Багато солі за день» |

Ключевые слова храним в `domain/rules/keywords.uk.ts`, поиск по нормализованному названию (нижний регистр, без апострофов) и по `food.tags`.

### 6.2 Режимы переопределяют правила
Если активен режим с `targetsOverride.carbs.min` (подготовка к ОГТТ):
- правило `glycemic` **не предлагает урезать** углеводы, а предлагает заменить быстрые на медленные
- в итоге дня показываем «не менше N г»

### 6.3 Вердикт по блюду целиком
`Підходить` — нет хитов кроме `ok`; `Підходить частково` — есть `adjust`/`replace`; показываем «3 з 5» и сводку.

### 6.4 Закономерности (Прогрес)
- Симптом X встречался ≥ 3 раз и в ≥ 70 % случаев в день, когда порция мяса за приём > 200 г → показать
- Средняя энергия в дни с тренировкой против дней без, если данных ≥ 10 дней

| D31 | Синхронизация между устройствами — по коду синхронизации (128 случайных бит, 26 символов Crockford base32), который знает только человек. Из кода на устройстве выводятся (HKDF-SHA256): id хранилища, ключ доступа (на сервере — только его SHA-256), ключ AES-GCM для записей и ключ HMAC для имён записей. Запись на сервере — `HMAC("таблица:id")` и шифротекст `{t, id, d, at}`, имя записи привязано как AAD. Изменения находятся по хэшу строки против последнего согласованного состояния (таблица `sync`), время изменения запоминается при первом обнаружении — даже офлайн. Конфликт по одной строке — побеждает более позднее изменение; при первой синхронизации устройства побеждает хранилище (пример плана нового телефона не затирает настоящий). Удаления — зашифрованные «надгробия». Встроенные продукты и блюда не синхронизируются. Когда: при запуске, возврате в приложение, появлении сети, через 3 с после изменения и раз в 2 минуты. Модель выбирает только названия из базы (enum в схеме ответа), граммы/штуки и время; приложение пересчитывает всё по своей базе, прогоняет свою проверку блюд (замены применяет, предупреждения показывает), не ставит приём позже «останній прийом до» и подгоняет порции к калориям (не больше чем на четверть). Черновик можно поправить (время, убрать позицию) или «Інший варіант»; «Прийняти» записывает приёмы со статусом «заплановано» и пометкой `menu` — новое меню заменяет только неотмеченные приёмы прошлого меню. Поради (2–5, практические, без медицинских) — на первом приёме, на «Дні» блоком «Поради на день». Лимит 15 меню на хранилище в день | «Не переписывать»: человек отмечает, что сделал, а не составляет день сам; лікар вирішує — меню строго в рамках плана |

## 14. Редизайн v1: «День» и запись еды (план, 2026-10-12)

Источники: макеты владельца (светлая, тёмная тема, лист «Підтвердити обід»), разбор Claude, шесть замечаний владельца после недели пользования.

**Что мешает сейчас:** карточки одного веса подряд — глазу не за что зацепиться; длинные строки показателей; технический язык («Додати рядок», «ЧАС · ПОЗИЦІЯ · ВУГЛ»); пустой день выглядит пустым, хотя план есть; «Зараз» вечером зовёт выполнить утреннее.

**Принципы (в дополнение к §1):**
- Одно главное действие на экране — оно визуально сильнее всего остального.
- План виден всегда: отсутствие записей не делает день пустым.
- Отсутствие галочки — не повод советовать принять пропущенное лекарство. Прошлое без отметки — «не відмічено», и только.
- Каждая быстрая отметка отвечает рядом с местом нажатия и отменяется.
- Цвет — только по смыслу: зелёный — сделано и главное действие, оранжевый — внимание, голубой — вода; остальное нейтрально.
- Без общего балла «насколько хорошо прошёл день».

### 14.1 «День» сверху вниз

1. **Шапка.** Название дня крупно («Сьогодні» / «Неділя, 11 жовтня»), под ним полоска недели Пн–Нд: выбранный день — тёмная плашка, точка под днём — «есть записи» (одно значение, без второго смысла), тап — переход к дню. Справа — значок синхронизации: облако с отметкой (зелёная галочка — синхронизировано, серое — выключено, оранжевое — ошибка); щит читался бы как «защита данных».
2. **Блок действия — три состояния вместо одного «Зараз»:**
   - **«Зараз»** — пункт плана, время которого в окне от −60 до +30 мин от текущего. Окно — правило показа, а не разрешение выполнить назначение в этот интервал: карточка говорит «через 20 хв · о 08:30» / «о 08:30 · 25 хв тому», требования плана («під час їжі») видны. Одна белая карточка с тенью — самый сильный элемент экрана. Название конкретно: «Вітамін D · 1 капс.», а не «Денний прийом». «Прийнято» / «З’їдено» — отметка временем нажатия; «Нагадати за 15 хв»; у приёма еды — «Пропустити» (позже — «Підтвердити», лист 14.3).
   - **«Не відмічено»** — пункты, которые человек сам запланировал и которым нужна отметка (ліки из плана врача, приёмы еды, записанные как «заплановано»), чьё окно прошло без отметки. Предложения «Меню» (`menu`) сюда не попадают. Свёрнуто в одну строку «Не відмічено · 3», по нажатию — список. У пункта «Відмітити» → «коли?»: «Щойно · 20:05», «О 08:30 — як за планом» (говорит человек, а не приложение), «Інший час», «Час не пам’ятаю» (`timeUnknown`, время не показывается и не попадает в отчёт как точное); время по плану хранится отдельно (у ліків — в `checkKey`, у еды — `plannedAt`), момент отметки — `markedAt`. «Пропущено» — запись `skipped`. Без слов «прийміть», «час прийняти». Сегодняшний экран показывает только сегодняшнее; вчерашнее неотмеченное остаётся на вчерашнем дне (видно, если открыть его) и не копится.
   - **«Далі»** — ближайший будущий пункт одной строкой («13:30 · Обід»), если «Зараз» пуст.
3. **«Записати їжу»** — заметная кнопка во всю ширину сразу под блоком действия (вместо «Додати рядок» внизу таблицы). Открывает запись еды с фокусом в поиске (14.2).
4. **Быстрые действия** — одна строка из 3–4 иконок с подписью: «Меню», «Мій стан», «Тренування» (и «Мій день»). Вода и ліки — не здесь, а на плавающих кнопках (D48), чтобы не дублировать.
5. **«Ритм дня»** — вертикальная линия времени из плана **и** записей: запланированные и съеденные приёмы, ліки по времени, тренировка (если день тренировки), «вечеря до 19:00». Сделанное — закрашенная точка и «Записано», будущее — пустой кружок, пропущенное — приглушено. Вода в линию не попадает (только кольцо), лекарства «раз на день» — одной строкой над линией. Тап по пункту — тот же лист действий (D46). Строка с действием («Меню ще не підтверджене · Переглянути») — вся строка нажимается, кнопка не сжимает текст. Пусто только если пуст и план — тогда одна фраза и «Записати їжу».
6. **«Уже сьогодні»** — 2–3 главных показателя, выбранных человеком (по умолчанию: вода, ліки, вуглеводи), каждый с целью или границей из плана, единицами и прогрессом: кольца для «набрать» (вода, ліки N з M, білок), полоса с подписью для «не превысить» («Вуглеводи · 82 г — межа 140 г», «межу не потрібно заповнювати»); в режиме с минимумом — «добрати не менше 150 г». Остальные (калории, білок, кальцій…) — по «Усі показники». Выбор главных — тут же, «Налаштувати».
7. **Плавающие кнопки ліки/вода (D48) остаются.** Ответ на нажатие — рядом с ними, не внизу экрана: пузырёк слева от кнопки «+250 мл · 1,25 л · Скасувати» / «Вітамін D · прийнято · Скасувати» на 5 с, кольцо обновляется сразу; повторный тап в эти секунды добавляет ещё 250 мл (и сумма в пузырьке растёт), а не открывает отмену.

### 14.2 Запись еды — еда первая

- Экран открывается с фокусом в поиске; подпись «Що з’їли — продукт, страва або кілька через кому» — разбор целой фразы («2 яйця, тост, кава» → три строки с галочками) уже есть (D30), подсказка ему соответствует; рядом фото и фото этикетки.
- Под поиском до ввода: **«Мої звичні»** — закреплённые человеком приёмы и блюда («Моя вівсянка», «Звичайний сніданок», «Кава з молоком»), затем «Часто» (D28). Закрепить — «☆ У звичні» у приёма в «Дні» и у блюда. «Як учора» остаётся на «Дні» (в меню «Меню» или в листе), но звичні — основной путь.
- Название приёма, время и «уже з'їдено» — одна компактная строка над кнопкой сохранения: «Обід · 13:30 · з'їдено ▾», подставляется по времени суток, правится тапом.
- Проверка блюда (§6) — как сейчас, вердикты у позиций.

### 14.3 Лист «Підтвердити прийом» (запланированное меню)

- Позиции с галочками — человек отмечает, что действительно съел; ничего не отмечено заранее.
- Рядом с позицией — только отличия от плана («Замінити», «Прибрати», «перевірте вагу»), а не «За планом» в каждой строке.
- Количество правится прямо в строке (± порция / граммы).
- Три разных состояния, не смешиваются: **предложение** (меню от ИИ, `menu`) — ещё ничего не обещает; **подтверждённый план** (человек сам записал «заплановано» или принял предложение в листе); **факт** (отмечено съеденным). «Записати вибране»: отмеченное — `done` со временем, которое человек подтвердил (как в 14.1); неотмеченное **не** становится «не відмічено» и не «пропущено» — его могли заменить, исключить или просто не подтвердить; оно остаётся предложением. Отдельная кнопка «Нічого з цього» → `skipped`.

### 14.4 Навигация и язык

- Вкладки: **День · Їжа · План · Прогрес · Ще** (пять, как сейчас). В «Ще» — Меню на завтра, Що купити, Звіт для лікаря, Нагадування, Мої страви и продукты, Синхронізація, Копія даних. Значок в шапке «Дня» — только статус синхронизации.
- Обращение: интерфейс сейчас на «ви» и от первого лица человека («Мій день», «Мої питання», «Мої продукти»). Заголовок «Сьогодні» вместо «Твій день»; кнопки — безличные или нейтральные по роду: «Прийнято», «Виконано», «Записано» (не «Прийняв»).
- Подзаголовки без пустых слов («Призначення з твого плану лікаря» → доза и «під час їжі»).

### 14.6 Порядок работ

1. **Логика без нового вида:** «Зараз / Не відмічено / Далі» (с «Пропущено» для ліків), обратная связь у плавающих кнопок — исправляет путаницу уже сейчас.
2. **Запись еды:** поиск первым, компактная строка приёма, «Мої звичні».
3. **«День» новым видом:** шапка с неделей, «Записати їжу», «Ритм дня» из плана и записей, «Уже сьогодні» с выбором показателей.
4. **Лист «Підтвердити прийом».**
5. Перенос нового языка на остальные экраны (План, Прогрес) — после недели пользования новым «Днём».

### 14.7 Что смотреть через неделю

Сколько времени занимает запись еды; где приходится искать действие; где возникают ошибочные отметки (лишние, не те, с неверным временем). Именно это покажет, удалось ли разгрузить голову.

На неделю фиксировать три вещи: где искал кнопку; где пришлось исправлять запись; когда решил ничего не вносить, потому что слишком хлопотно (главное для исходной задачи). Отдельно — нужны ли все пять плиток и пользуюсь ли «Мій день» отдельно от «Ритму дня».
